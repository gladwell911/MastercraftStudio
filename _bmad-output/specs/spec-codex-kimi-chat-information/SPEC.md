# Codex/Kimi 聊天信息列表

## Why

桌面端用户无法在当前聊天中可靠地同时查看上下文占用、会话累计消耗和账号额度；现有上下文行将 Codex 累计 token 误作上下文占用的风险使数值失真。用户需要一个不打断任务和键盘浏览的信息入口。

## Capabilities

- **CAP-1**
  - **intent:** 用户可从顶部“应用(&A)”菜单打开当前 Codex/Kimi 聊天的独立信息列表，并用键盘浏览和关闭。
  - **success:** 仅 Codex/Kimi 聊天可用“查看聊天信息”；打开后焦点在列表，方向键可逐行浏览，列表焦点按 Esc 关闭并恢复打开前焦点，主窗不最小化。
- **CAP-2**
  - **intent:** 用户可查看当前上下文已用比例及精确已用和窗口总 token。
  - **success:** 两种引擎均显示 `已用百分比（已用 / 总窗口 token）`；压缩或切模型后的权威值更新，未知窗口或尚无用量时逐项标注不可得。
- **CAP-3**
  - **intent:** 用户可查看当前原生会话的累计 token 消耗，并与上下文占用区分。
  - **success:** Codex 展示 thread 累计 `totalTokens`；Kimi 展示 session 累计输入加输出 token；重开面板与切换聊天后数值归属正确。
- **CAP-4**
  - **intent:** Codex 用户可查看周额度剩余比例和具体重置时间。
  - **success:** 服务端提供周窗口时显示剩余百分比和本地日期时间；无周窗口或 API key 账号时显示明确不可用状态。
- **CAP-5**
  - **intent:** Kimi 用户可查看五小时和七日额度的使用情况。
  - **success:** 托管 OAuth 账号有相应字段时，五小时行显示已用百分比和本地具体重置时间，七日行显示已用百分比和距重置时长；缺字段时对应行明确不可得。
- **CAP-6**
  - **intent:** 用户打开信息列表期间可看到随服务端变化更新的数值，且键盘浏览不中断。
  - **success:** 用量事件更新上下文与累计值，账号额度通过打开时及可见期间低频刷新更新；无可见变化时不重绘或改动选择、焦点，关闭后停止刷新。
- **CAP-7**
  - **intent:** 用户能识别账号、网络和协议字段导致的数据不可用或过期。
  - **success:** 每行分别显示未登录、不适用、暂不可用或上次更新状态；失败时不把缺失值渲染为 0，也不把缓存值称为实时值。

## Constraints

- 数据字段、单位、刷新和回退规则以 [data-contract.md](data-contract.md) 为准；当前上下文与会话累计消耗不得混用。
- Codex 仅展示主 `codex` 额度类别的周窗口；其他额度类别不进入聊天信息列表。
- 面板与异步结果绑定打开时的聊天、原生 thread/session 和账号身份；旧结果不得写入后来切换的聊天或关闭的窗口。
- 保持屏幕阅读器键盘体验：后台无可见变化时不调度 UI 工作、不重绘列表、不改变选择或焦点；相关 GUI 测试串行。
- Esc 在信息列表中先关闭面板，不能触发主窗口现有的最小化到托盘行为。

## Non-goals

- 不显示绝对账号配额、余额或 token 换算值；官方接口只提供所需窗口的比例。
- 不改变 Codex/Kimi 任务、消息送达、停止行为或手机端界面。
- 不把显示刷新定义为逐 token 的实时计量。

## Success signal

在 Codex 和 Kimi 各自执行与空闲的聊天中，用户通过顶部“应用(&A)”菜单打开信息列表，能读到正确归属的上下文、累计消耗和账号窗口信息；服务端返回变化后列表只更新变化的行，方向键浏览和 Esc 关闭始终保持焦点稳定。

## Assumptions

- “会话累计 token”指当前原生 Codex thread 或 Kimi session 的累计输入与输出 token，包含缓存输入但不重复加缓存子项；新建原生会话后从新会话重新累计。
