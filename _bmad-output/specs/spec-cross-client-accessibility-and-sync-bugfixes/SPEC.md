# 跨端无障碍、状态反馈与同步缺陷修复

## Why

手机端和桌面端存在延迟导航、状态反馈缺失、焦点行为不一致、持久化回写以及列表陈旧内容等问题。它们会让用户误判程序卡死、使屏幕阅读器操作失去可预测性，并破坏电脑端与手机端之间的状态一致性；本次工作要恢复可感知、可控制且跨会话稳定的核心流程。

## Capabilities

- **CAP-1**
  - **intent:** 手机用户启动“传输到手机”“打开文件”或“下载文件”后，可以立即进入对应进度界面并持续获知准备、连接、等待、下载、失败或完成状态。
  - **success:** 点击后首个可渲染帧已进入目标进度界面，耗时操作不会阻塞导航，并且每次状态变化都在该界面准确呈现。
- **CAP-2**
  - **intent:** 手机用户可以通过一个暂停/继续切换按钮和一个停止按钮控制文件传输。
  - **success:** 两个按钮在所有传输状态下都可被聚焦和点击；适用动作改变传输状态，不适用动作安全无操作。
- **CAP-3**
  - **intent:** 手机用户可以在设置中控制是否呈现电脑端回复的推送通知。
  - **success:** 开关默认开启；开启时电脑端回复可产生通知，关闭时同类通知不再呈现但回复数据仍在后台接收和同步，且设置在应用重启后保持。
- **CAP-4**
  - **intent:** 手机用户可以看到电脑端当前实际选定的模型。
  - **success:** 电脑端切换到任一受支持模型后，手机菜单在状态同步完成后显示同一模型，不再固定显示 `codex`。
- **CAP-5**
  - **intent:** 用户完成临时详情操作后可以回到对应聊天详情，而不会再次落入已完成的临时页面。
  - **success:** 手机端打开提取文件后再次进入相关流程时显示聊天详情；桌面端在回答详情点击“继续”后立即显示聊天详情。
- **CAP-6**
  - **intent:** 手机用户删除聊天后，该聊天保持删除状态。
  - **success:** 被删除聊天在当前列表、页面往返、后台刷新及应用重启后均不再出现，过期缓存或远端旧快照不能将其复活。
- **CAP-7**
  - **intent:** 手机用户在文件标签中可以用最少信息识别文件及其当前处理状态。
  - **success:** 每条文件记录只呈现文件名和一个准确的当前状态，至少覆盖准备中、连接中、等待接收、正在下载、已暂停、已停止、下载失败和已完成。
- **CAP-8**
  - **intent:** 桌面用户在指定列表或模型选择框中可以用一次空格快速回到输入框。
  - **success:** 焦点位于笔记列表、历史聊天列表、回答列表或模型选择组合框时，按一次空格产生与一次 `Alt+D` 相同的输入框焦点结果。
- **CAP-9**
  - **intent:** 手机用户点击命令按钮中的命令时可以听到系统标准点击反馈。
  - **success:** 每次有效命令点击都会触发平台系统点击音效，且不重复播放或替换为自定义提示音。
- **CAP-10**
  - **intent:** 手机用户进入笔记详情后可以直接使用文字输入，并能切换到语音输入。
  - **success:** 页面首次显示时处于文字输入模式，底部显示编辑框，左下角显示切换到语音输入的按钮。
- **CAP-11**
  - **intent:** 屏幕阅读器用户可以按原段落结构逐行阅读多行笔记。
  - **success:** 多行笔记按原换行显示，每个非空文本行均形成独立、按原顺序可到达的屏幕阅读器焦点。
- **CAP-12**
  - **intent:** 手机用户在回答详情中获得与聊天详情一致的底部操作布局。
  - **success:** 两个页面的共用底部按钮顺序和位置一致，回答详情的“提取文件”按钮位于右下角主按钮上方。
- **CAP-13**
  - **intent:** 用户在回答列表和执行列表中只看到属于当前聊天和当前条目的内容。
  - **success:** 列表尾部不再出现先前回复的内容；切换聊天、增量更新、刷新和重新进入页面均不会产生陈旧尾项或重复尾项。

## Constraints

- 手机端位于 `rc` Flutter 项目，桌面端位于 `mc` wxPython 项目；共享状态或协议变更必须保持两端兼容。
- 所有 UI 改动必须保持屏幕阅读器语义、可预测的键盘焦点和稳定导航；传输控制按钮不得通过禁用语义从辅助技术中消失。
- `mc` 后台轮询在没有可见状态变化时不得调度 UI 线程、重绘列表、改变选择或焦点、写入应用状态。
- 文件准备、连接和下载不得阻塞首次页面导航；目标页面先显示，异步工作随后更新可见状态。
- 聊天删除以持久化与同步层的确定状态为准，过期缓存、后台刷新或远端旧快照不得复活删除项。
- 每项 UI 修复必须运行对应的定向无障碍或 UI 自动化回归测试；跨端状态修复还必须覆盖持久化、协议或模型工作流测试。

## Non-goals

- 不重新设计整套手机导航、聊天协议、文件传输协议或桌面快捷键体系。
- 不改变聊天、文件或笔记的内容，只修复呈现、交互、持久化和同步一致性。

## Success signal

用户能够在点击后立即获得可读的进度反馈，使用屏幕阅读器稳定完成文件、聊天和笔记操作，并且模型、删除结果及列表内容在跨页面、跨端和重启后保持一致。`acceptance-criteria.md` 中的全部场景通过定向自动化测试或真实设备演示。

## Assumptions

- “按钮在任何状态下可用”表示按钮始终可聚焦且不暴露 disabled 语义；动作不适用时处理器安全无操作。
- “立即进入界面”表示点击后的首个可渲染帧完成导航，耗时准备、连接或下载在目标页面启动。
