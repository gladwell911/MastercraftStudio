# 验收条件

本文件将原始 16 条缺陷逐条映射到稳定能力 ID。除特别说明外，每项都需同时验证视觉呈现、屏幕阅读器语义和页面往返后的状态。

## 文件传输与下载

- **AC-1.1（原问题 1，CAP-1）**：提取文件后点击“传输到手机”，应用先进入传输界面，再开始文件准备或电脑端连接；界面连续呈现当前阶段，期间不出现无反馈等待。
- **AC-1.2（原问题 12，CAP-1）**：点击“打开文件”或“下载文件”，应用先进入下载界面，再执行耗时工作；下载界面呈现准备、等待、下载、失败和完成中的实际状态。
- **AC-2.1（原问题 2，CAP-2）**：传输界面只提供一个随状态切换名称和动作的“暂停/继续”按钮，以及一个“停止”按钮。
- **AC-2.2（原问题 2，CAP-2）**：两个按钮始终保留可聚焦、可点击语义；动作不适用时点击不会改变传输、抛出异常或造成错误提示。

## 通知、模型与跨端状态

- **AC-3.1（原问题 3，CAP-3）**：设置页存在可被屏幕阅读器正确识别名称、值和状态的推送通知开关。
- **AC-3.2（原问题 3，CAP-3）**：开关默认开启；开启时电脑端回复能产生手机系统通知；关闭时不呈现同类通知，但回复仍在后台接收并同步；重启应用后设置不回退。
- **AC-4.1（原问题 4，CAP-4）**：电脑端分别选择至少两个非 `codex` 模型后，手机菜单显示对应模型；切回 `codex` 时也同步显示正确。
- **AC-6.1（原问题 6、13，CAP-6）**：从聊天列表删除聊天后，该项立即消失；进入其他页面再返回、等待后台刷新及退出重进应用后均不恢复。
- **AC-6.2（原问题 6、13，CAP-6）**：删除与远端同步或本地缓存刷新并发时，删除结果仍获胜且不会产生重复记录。

## 导航与列表呈现

- **AC-5.1（原问题 5，CAP-5）**：手机端从提取文件界面执行“打开文件”后，临时路由状态被消费；下次返回相关聊天时显示聊天详情。
- **AC-5.2（原问题 9，CAP-5）**：桌面端回答详情点击“继续”后，焦点和可见页面均回到对应聊天详情。
- **AC-7.1（原问题 7，CAP-7）**：文件标签的每条记录只包含文件名和单一当前状态，不显示路径、大小、内部 ID 或其他非要求信息。
- **AC-7.2（原问题 7，CAP-7）**：状态至少准确区分准备中、连接中、等待接收、正在下载、已暂停、已停止、下载失败和已完成，并随真实处理状态更新。
- **AC-12.1（原问题 15，CAP-12）**：回答详情与聊天详情的共用底部按钮顺序、间距和屏幕阅读器遍历顺序一致；“提取文件”位于右下角主按钮上方。

## 桌面键盘与焦点

- **AC-8.1（原问题 8，CAP-8）**：分别将键盘焦点置于笔记列表、历史聊天列表、回答列表和模型选择组合框，按一次空格后输入框获得焦点。
- **AC-8.2（原问题 8，CAP-8）**：快捷键不会触发列表默认动作、改变模型选择或插入空格；不在指定控件时保留原有空格行为。

## 命令与笔记无障碍

- **AC-9.1（原问题 10，CAP-9）**：点击命令按钮中的任一有效命令时只播放一次系统点击音效，命令执行结果与改动前一致。
- **AC-10.1（原问题 11，CAP-10）**：进入笔记详情的首次渲染即为文字输入模式，编辑框位于底部，左下角为语音输入切换按钮。
- **AC-11.1（原问题 14，CAP-11）**：包含多行文本的笔记保留原换行；屏幕阅读器可按原顺序逐行移动焦点并朗读该行，不把整篇文本合并成单个焦点。

## 内容正确性

- **AC-13.1（原问题 16，CAP-13）**：在同一聊天连续产生多条回复和执行记录时，回答列表与执行列表的尾部只显示当前数据，不附带上一条回复内容。
- **AC-13.2（原问题 16，CAP-13）**：聊天切换、增量事件到达、页面刷新和重新进入详情后均不出现旧尾项、重复尾项或跨列表内容污染。

## 回归验证底线

- `mc` 的每项 UI 改动运行相关 `tests/test_*ui_automation.py` 以及受影响的模型工作流测试。
- `rc` 的每项 UI 改动运行相关 widget/integration 测试；通知、文件、聊天删除和模型同步至少各覆盖一个持久化或端到端场景。
- 真实设备验证需要确认 TalkBack 焦点顺序、按钮名称/状态、系统点击音效和通知开关行为。
