# MC 桌面聊天的工具设置、历史接续与用量

## 用户问题与目标

使用读屏软件时，用户需要在一个窗口内确定“接下来由哪个工具、用什么配置回答”，并听清这次操作会追加到当前回合，还是提交独立提问。现在工具和模型混在同一选择框里，AGY 新建还要连续选择目录与配置。在已有 Codex 聊天中改选 AGY 后直接发送，会因缺少 AGY 会话而失败。原生终端导入的大量聊天也会挤占历史列表，用户在打包程序中遇到键盘浏览卡顿和“未响应”。AGY 聊天按 Alt+Y 无法查看统计。

## 用户故事与行为

1. 我可以在 Alt 工具菜单勾选“隐藏终端聊天”，只浏览由 MC 创建的聊天。再取消勾选时，原有历史恢复可见。设置在重开 MC 后保留。MC 创建的聊天即使后来在终端续聊，仍归 MC 创建。
2. 我可以用键盘依次操作“工具”“模型”“推理强度”“速度”四个有中文名称的组合框，并听到当前值。工具依次排列为 Codex、AGY、Kimi Code、其他工具。选中其中一个后，其余选项随工具及所选模型实际可用的配置更新。供应商的模型名照原名显示，设置项、提示和可本地化的档位以中文呈现。
3. 我可以从工具菜单选择当前工具支持的工作模式。选择模式与设置文件访问范围、工具审批分别生效。已有的其他工具仍可从原来的发送流程使用。
4. 我可以选择 AGY 后直接新建聊天，输入问题并发送。新建采用与 Codex 相同的默认工作目录，主界面的待发送设置代替目录与配置弹窗。默认配置为 Gemini 4 Neon、推理强度高、自动模式。该模型在本机真实配置中的标识为 `gemini-4-neon`。
5. 我可以在同一个工具的聊天中修改模型或推理强度并提交下一问。旧问答仍可见，已提交的回合使用其原设置，新回合使用提交时选定的设置。各工具的原生会话 ID 保持一致。
6. 我可以在 Codex 聊天中改选 AGY，继续编辑草稿。只有实际发送时才按原聊天的工作目录创建独立 AGY 聊天并提交，原 Codex 聊天和任务继续保留。改回 Codex 或离开控件不会生成空聊天。
7. 我可以在 AGY 中基于前面已经结束的可见问答继续。交接包含截至交接位置的全部已完成问答原文，保留发言顺序、真实来源与换行，再附本次问题。超出可接受长度时，MC 提示未发送，保留源聊天、原草稿和本次附件，供我调整。
8. 我可以在 AGY 聊天按 Alt+Y，用读屏逐行读取当前上下文、会话累计 token、当前缓存命中、累计缓存命中和账户限额。三个工具的额度重置时间都按本地周几和几点几分播报。

## 实现与验收约定

### 历史与键盘响应

工具菜单的两个入口共享同一个勾选值。过滤依据聊天的创建来源。对已有数据，可用原生历史映射与聊天自身 ID 的关系识别导入项。新旧记录均需覆盖，不能仅凭模型、标题或是否带原生会话 ID 判定。整表刷新、增量更新、置顶排序、键盘前后切换共用可见集合。隐藏选中的行时维持有效选择与键盘焦点，保留正在进行的会话及其数据。此开关只改变桌面历史的呈现，不写入单条聊天的隐藏或删除标记。

针对用户报告的冻结包，在隔离副本中对比相同数据下显示全部与仅显示 MC 聊天、空闲与同步期间的操作延迟。记录按键到列表选中或焦点反馈、主线程长操作和发生时间。已见 1,224 条聊天中有 1,204 条使用原生导入 ID，逐行查询未读与反复线性查找是优先验证项。先减少已确证的重复查询、遍历和不必要的控件重绘，无变化时保持选中和焦点。读屏听感、程序未响应与单个查询耗时分别记录，若无法复现卡死，交付只陈述已测改善及缺少的现场证据。

### 待发送设置与新建

- 控件使用供应商报告的模型、推理强度及速度。Kimi Code 或 AGY 未提供独立快速服务档位时，速度框默认显示“标准”。仅有一个速度选项时，保持读屏可获取当前值。其他设置缺项时，提示“此工具不支持”。更换工具或模型后，不沿用无效的旧选项。显式选择和发送使用同一组原始标识，缺失的默认配置必须清楚告知。
- 工具组合框只列“Codex”一次。原来的 Codex 5.4、5.3 等预设从工具框移出，可用模型按供应商目录在模型框列出。Codex 按模型报告的推理强度、服务档位填充选项。标准与快速使用实际服务档位。协作模式与审批策略、访问权限分别设置。新建采用默认协作模式，默认免逐次审批和完全访问，对应原生 `never` 与 `danger-full-access`。
- Kimi Code 根据当前受支持的 CLI 和真实模型能力提供配置。Highspeed 若为单独模型别名，保留实际模型映射及提供方给出的额外用量提示。思考能力以该模型报告的档位为准，计划模式、权限模式分别处理。新建关闭计划模式，权限默认选择 auto，以免逐次询问为目标，保留当前 Windows 用户与运行环境的访问边界。须验证所装版本真正接受并执行该设置；参数写入成功和实际出现审批的情况均需如实记录。
- AGY 使用当前 ACP 会话广告的选项。默认模型 Gemini 4 Neon、`thought_level=high`、`mode=auto`。工作模式与 MC 启动 AGY 已采用的跳过逐次工具审批参数分开处理。设置标签和档位中文化；同一工作目录内的正常任务能直接执行，后续提示词可指向其他工作位置；会话显示的工作目录以真实绑定为准。

### 同工具新回合与回合内追加

当模型或推理强度有待生效变更，普通发送创建独立提问，为它保存发送时的工具、模型、推理强度、速度和模式。旧回合在执行时，先接收新提问并排队，待原回合结束后在同一原生会话应用新设置、启动新回合。连续修改设置并提交两问时，两问各自保留提交时的快照，按提交顺序执行。模型和推理强度均未更改时沿用该工具现有的普通发送行为。明确对原回合执行“追加”的输入仍归原回合，沿用该回合的配置，沿用现有输入和发送控件。配置切换失败时应提示错误并保留可恢复的问题，不可静默改用其他模型。

保留三个后端原有的可用能力和准确反馈。Codex 与 AGY 在可定位活跃回合时支持原回合追加。Kimi 2.5.3 使用已确认的追加协议，2.6.3 当前 MC 将已提交的后续输入保留为独立排队请求；要求同轮追加而实际只能排队时，需让用户听清差异。重开、切换可见聊天、回合结束与提交并发时，问题、配置和完成状态仍属于各自的聊天及回合。

### Codex 转 AGY

切换工具只更新待发送设置。发送时先确定源聊天、真实工作目录、交接截止位置和源聊天已持久化的可见问答，再校验目标会话能力与输入规模。已经结束的原文完整带入，未完成回合的片段、内部推理、工具轨迹、缓存与历史附件二进制均不随历史隐式传送。新问题显式附带的文件按 AGY 原有能力提交。目录不可用或输入超限时说明具体原因，保留原聊天和草稿，不缩写、截断或换目录。

新 AGY 会话首次提交把交接原文和本次请求组成一次原生 prompt，不预发历史或生成寒暄回合。历史标识为过去的对话，本次提问独立标识。保留原 Codex 聊天的身份和可返回的位置，后续 AGY 提问直接复用新会话；只有第一次请求带交接原文。首次提交若明确被拒或用户取消，回到可编辑的原状态。若已发送但响应丢失，确认同一会话及请求结果后再处理，避免重复提问或空白分身。直接“新建 AGY 聊天”则从空白开始，使用默认目录。

### 聊天信息与时间

AGY Alt+Y 使用可见聊天的原生会话身份获取统计，重开及切换聊天后同样可读。当前上下文用 ACP 已用 token 与窗口大小；会话累计 token 根据供应商累计值或可按唯一请求去重的真实消耗计算。当前、累计缓存命中分别展示供应商实际提供的值及单位，命中率仅在同口径分子和分母齐全时计算。账户额度按账号、当前机器和供应商隔离，与会话计量分别存取；读屏浏览期间后台更新保持焦点。

AGY 逐行显示周限额、5 小时限额、Claude 和 GPT 共用的周限额，每行有剩余用量及重置时间。Codex 额度只显示周额度。Kimi 保留其实际可用的 5 小时和周额度。后台取数失败、未登录、账户不适用、部分数据缺失或已过期时，显示相应状态，不能用零、上个账户的数据或当前上下文占用率代替。

保留供应商原始时间，展示时按本地时区、以周一为每周起点。举例，本周五显示“周五 14点05分”，下周一显示“下周一 09点30分”。周日跨到周一以及跨月、跨年都按同一规则。旧缓存仅有成品日期字符串时，按真实响应刷新。该显示约定针对额度重置时间。

## 验证与交付

1. 使用现有 wx 桌面键盘自动化，从组合框、Alt 菜单、发送和 Alt+Y 进入，验证 Tab 顺序、中文可访问名称、工具对应选项、焦点、过滤和错误后草稿。用真实历史量级的数据测两种过滤状态。若有真实读屏与打包版实测，记录包版本、操作路径和观察到的结果。
2. 在隔离配置和测试聊天中，从 MC 的正常发送入口分别跑通 Codex、Kimi Code、AGY。每家从配置 A 完成至少两条问答开始，在随后的回合核对前面问答仍可读且原生上下文保留，分别验证仅更换模型、仅更换推理强度、同时更换两者的提问，以及上轮仍运行时这些新提问进入队列，在同一原生会话按各自提交快照开始新回合。若实机仅提供一种强度，记录这一事实及阻止该场景验收的限制。用供应商设置回执、原生读回或实际请求参数核对生效值和相同会话 ID；回答中自报型号不能单独作为证据。分别记录版本、支持的字段、排队/追加行为及新会话默认权限的实际工具操作结果。对当前支持的两版 Kimi 验证相应行为。只通过模拟测试的项目单列，不算三家端到端通过。
3. 从已完成多轮且有唯一可核对内容的 Codex 聊天，验证只选择 AGY 不发请求，首次发送才创建 AGY 独立会话。核对目录、首个请求收到的完整原文和新问题、仅一条实际提交、下一问不重发，以及旧 Codex 会话仍可打开。另验包含未完成回合、超限、目录无效、明确失败和结果未知时的行为。
4. 用有代表性的真实 AGY 接口或原生数据核对累计消耗、缓存与三个额度窗口的口径、账号归属和重置时刻。优先核实本机 AGY 1.5.18 的原生 /usage 与可读数据。供应商公布了分模型组的额度与细分 token 类型，实际可机读通道、版本和字段必须用本机响应确认。分别验证缺字段、未登录、两账号或两会话切换以及本周/下周边界。缺乏实证的字段保留为明确待验项，不能用构造样本宣称真实用量已接通。

工作范围为 Windows MC 桌面及其必要的本机后端适配。此次规格不扩展手机界面、其他工具之间的全向迁移或正式部署。
