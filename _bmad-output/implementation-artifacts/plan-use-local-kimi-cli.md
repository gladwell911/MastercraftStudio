# MC 改用本机 Kimi CLI 的实施计划

状态：仅完成计划，尚未改代码、验收 2.6.3、构建或部署。实际切换须等以下门禁通过。

## 目标与现状

MC 继续使用现有 Kimi 本地服务及客户端协议，从每台 Windows 电脑已安装的 CLI 启动。新安装包不再携带 `kimi.exe`，标准用户可在 MC 外管理安装和升级。缺失或不兼容时，Kimi 提供能被读屏读取的错误，MC、Codex 和历史浏览仍可用。

当前 `kimi_server_client.py` 从显式 `KIMI_BIN` 或包内目录解析可执行文件，并由 `kimi_runtime.py` 验证 2.5.3 与固定 SHA-256。`zgwd.spec` 收集前验证该文件，`package_mc.ps1` 验证暂存及最终包。本机候选为 `C:\Users\gaope\.kimi-code\bin\kimi.exe` 的 2.6.3，历史 2.5.3 证据只适用于原构建。 [运行时文档](../../docs/kimi-runtime.md)

## 实施顺序

1. **先验证 2.6.3。** 记录候选来源、绝对路径、架构、版本输出和 SHA-256。在临时 `KIMI_CODE_HOME`、独立 MC 历史和现成隔离测试设施中运行真实 CLI，按下表验证协议和旧历史。先核对实际握手、订阅、推送和 REST 样本，再修改适配器。涉及真实云端时使用独立认证环境，探针和记录均不包含凭据或真实聊天正文。
2. **定位和权限。** 优先使用显式 `KIMI_BIN` 的本机绝对路径，再尝试 `Path.home() / '.kimi-code' / 'bin' / 'kimi.exe'`。显式路径无效时报出错误及路径。直接传 argv 启动 EXE，使用当前用户权限，覆盖带空格和中文的路径。CLI 安装权限由每台电脑自己管理，MC 在探针和服务进程都设置 `KIMI_CODE_NO_AUTO_UPDATE=1`。Kimi 程序路径与 Codex 的 OneDrive 代理配置独立。
3. **版本与协议。** 以已验证的发行构建作为初始支持记录，核对版本和 SHA-256，并在运行时核对握手与受支持的协议。手动升级后出现未知构建时，提供当前路径、检测到的版本与下步操作，等待验证和发布支持记录。保留已有 V1/V2 行为与 V2 当前连接 ACK 门禁，保持 chat、turn、session、account、request generation 的归属检查。活动请求结果未决时保留原身份用于恢复，切换运行时不得触发自动重发。
4. **数据与回滚。** 用可丢弃的旧会话样本验证历史文本、累计用量、继续问答与退出重开，并单独核对 2.6.3 写过的样本能否由 2.5.3 读取。若数据格式无法降级，先停用 Kimi，由用户退出 MC，再按已验证流程切回兼容的本机 CLI 或恢复切换前的数据快照。任何需要覆盖含新增聊天的数据恢复都要先核查差异并单独确认。既有 MC 聊天、Codex 会话和 OneDrive 笔记在发布前后按项目切包门禁核对。
5. **解除打包依赖。** 在 `zgwd.spec` 移除 Kimi 固定 DATA 项及构建前的固定文件验证，在 `package_mc.ps1` 移除包内 Kimi 的暂存/最终检查并增加产物不含 Kimi 可执行文件的检查。更改自定义 spec 交付约定和测试。在临时 `DistPath`、`WorkPath` 全新目录运行 `-BuildOnly`。用不装本机 Kimi 的隔离环境独立确认 MC 与 Codex 可启动，再用装有已支持版本的标准用户环境验收 Kimi。另用隔离的旧安装目录核对切包后没有遗留包内 Kimi，清理只处理已确认的旧程序文件和链接节点。日常程序更新与启动沿用项目部署规则。

## 验收矩阵

| 场景 | 通过条件 |
| --- | --- |
| 本机定位与权限 | 笔记本、台式机分别从本机路径启动。显式有效覆盖生效。显式失效、无安装、无权限、未知构建、握手失败各有可读状态，Codex 可继续使用。 |
| 真实 2.6.3 流式问答 | 目标会话订阅 ACK 后才发送。同一会话连续两问，中文和非 BMP 字符增量与终态全文一致，归属、用量和持久化正确。 |
| 取消、追问与归属 | 真实 `/stop` 与活动追问走原有精确 owner。旧连接事件、旧请求代次、重复终态和清空后的迟到结果不会写入新会话。 |
| 断线与旧历史 | 模拟掉线、日志覆盖与服务重启，验证同一 prompt 的增量补齐及 REST 恢复，正文完整且无重复发布。旧历史可读，比较切换前后的会话身份和累计用量，并单独记录降级兼容结论。 |
| 独立打包 | `tests/test_packaging_specs.py` 通过。干净源码副本无需准备旧 Kimi 二进制即可构建，产物包含 MC 两个入口且无 Kimi 可执行文件。冻结 GUI 两种本机环境通过，缺安装的提示可由键盘和读屏读取。 |
| Codex OneDrive 回归 | 保留当前 Codex 代理读入与本机覆盖的配置契约。分别用两台机器身份、有效配置与缺失文件启动实际打包 worker，核对 Codex 实际子进程收到预期变量，Kimi 不接收该链路专属变量。用独立 Codex home 核对启动、首问与会话复开。真实代理环境记录首条响应时间与 WebSocket/HTTP 回退日志。 |
