# Kimi Code CLI 2.6.3 ACP 与 Server API 对照结果

## 环境与结论

2026-11-23 在笔记本 Windows x64 上运行。两条路线使用同一个已安装的 `C:/Users/gaope/.kimi-code/bin/kimi.exe`，SHA-256 为 `b50c7ce3bed69e9be58f9a29aa090c0e7c61f7a1887503c4943267384a71ef30`。ACP 通过 `kimi acp` 的 JSON-RPC stdio 协商到 v1。Server 通过 `kimi web --no-open --port <隔离端口>` 启动，使用 Bearer REST 与 `kimi-code.bearer.*` WebSocket 子协议，收到目标订阅 `response.code=0` 后提交。Server 的应用层 `ping` 需要回 `pong`。每条路线使用独立临时工作区和 `KIMI_CODE_HOME`，禁用 CLI 自动升级。

两条路线均能经真实 CLI 驱动本地可控模型，执行基本对话、工具审批与取消。两条路线都没有通过真实模型和 MC 交付门槛。本次未接入或修改 MC、未部署，台式机与实体读屏未验证。

## 八项实测

| 功能 | ACP | Server API |
| --- | --- | --- |
| 聊天与流式 | **通过（底层回环）**。同一会话连续两问收到中文和非 BMP 字符，拼接结果与标记精确一致，均以 `end_turn` 结算。冷重启可加载原标记。 | **通过（底层回环）**。同一会话连续两问，收到 `item.delta` 和 `turn.ended`，REST 历史含完整标记。真实模型对第二问的理解没有验收。 |
| 工具与审批 | **通过（底层回环）**。只读操作完成。两次使用相同中文带空格目标名，审批前均无文件，拒绝后仍无文件，批准后实际创建。 | **通过（底层回环）**。按会话和 `interaction_id` 回答审批，拒绝后目标不存在，批准后才创建。读屏未测。 |
| 执行过程 | **可用但降级**。读、写、echo 均观察到 `pending`、`in_progress` 和 `completed`，拒绝写对应 `failed`。执行步骤恢复与 MC 映射未验收。 | **可用但降级**。收到工具 `item.started/updated/ended`，echo 还收到 task 事件。重开后逐步内容、错误细节与 MC 映射未验收。 |
| 取消 | **通过（底层回环单次）**。首段到达后发 `session/cancel`，提示词结果为 `cancelled`，下一问成功。 | **通过（底层回环单次）**。发对应 prompt 的 `:abort` 得到 `aborted=true`，约 0.032 秒后收 `user_cancelled`。该取消场景未安排写入任务。 |
| 重连与恢复 | **可用但降级**。完成后可加载原会话，冷重启后读回标记约 0.109 秒。活动 stdio 中断后接回同一未决任务未验证。 | **可用但降级**。活动期间关闭 WS 后重新订阅，未重发 prompt，约 1.187 秒收到终态，REST 读到标记。活动服务进程冷重启后恢复待验收。 |
| 途中追问 | **可用但降级**。当原轮仍在流式输出时，第二次 `session/prompt` 返回 `-32600`，原轮继续完成。仅验证了该提交入口，没有验证 ACP 扩展。 | **可用但降级**。`POST /steer` 接受新内容，原轮 ordinal 0 结束，追问形成 ordinal 1 并结束，历史中两段可查。此次普通流式夹具未证明同轮无缝更新。 |
| 用量 | **可用但降级**。回环样本中 `usage_update` 给出 `used=110`、`size=32768`。首轮未观察到该帧，累计、缓存命中率和冷重启复现未证实。 | **可用但降级**。收到含 `context_tokens`、`max_context_tokens` 的帧，终态 turn 有 `usage` 字段。完整单轮和累计口径、缓存分母与恢复未核对。 |
| 附件 | **可用但降级**。内嵌 TXT 标记和 PNG 字节传到回环模型。将合成 PNG 声明为 PDF 时字节也到达，未见可读预检错误。没有验证真实视觉识别、真实 PDF 或恢复。 | **可用但降级**。中文空格文件名作为 TXT 路径附件进入 REST 历史，本场未证明 TXT 字节自动注入模型。PNG 字节到达回环模型。错误 MIME 声明仍被接受，未证实真实 PDF 处理。 |

## 计时与真实云端失败

回环三次独立首问，按第一条正文增量到终态分别列出秒数。此处测协议帧，未测 UI 可见时延。

| 路线 | 第一次 | 第二次 | 第三次 | 中位数 |
| --- | --- | --- | --- | --- |
| ACP | 0.016 / 0.110 | 0.016 / 0.125 | 0.016 / 0.109 | 0.016 / 0.110 |
| Server | 0.094 / 0.141 | 0.094 / 0.141 | 0.109 / 0.140 | 0.094 / 0.141 |

真实阶段加载同一来源的临时认证副本。两条路线都达到了各自的本地初始化和会话建立。ACP 首问 45 秒内只收到 `available_commands_update` 和 `session_info_update`，无模型正文或提示词终态。Server 订阅和本地 prompt 提交已受理。补齐应用心跳后，最短失败证据来自首个 `turn.updated.retry.error`，内容为 `Stored token for "kimi-code" was rejected; re-login required.` 同一运行还观察到 CLI 多次重试，最后 `turn.ended` 的 `end_reason=error`，始终没有助手文本增量。这证明 Server 调用云提供方受认证阻断。ACP 使用相同配置和认证内容，现象与这一共因一致，ACP 本身没有返回能单独证实的同一错误。未触碰日常登录，临时副本已清理。真实云端三次首问、三次恢复、中位数和所有依赖成功云请求的验收均未完成。

事件探针仅比较实际观察到的样本。回环审批样本未发现提前写入，断线样本没有客户端重发。没有完成并发串会话、跨机隔离或长期非授权写入统计。现有 MC 仍不能据此切换；若继续对照，先使用可独立登录的测试身份获取真实模型应答，再复跑两路关键功能。

## 重新登录后的 Server API 真实模型复测

用户在独立 Kimi home 内完成登录，登录进程退出码为 0。笔记本上的同一 2.6.3 二进制通过 Server API 探针访问真实模型。三个独立新会话的第一条增量分别为 1.328、0.766、0.812 秒，对应回合结束时间为 3.046、1.563、1.984 秒。三个会话均产生增量和历史标记，第一会话的第二轮也完成。这些是从探针提交到协议事件的计时，包含的首条增量可能是思考内容，未测 MC 界面可见正文时延。

- 在独立临时工作区拒绝写入审批，目标文件未创建。批准另一独立任务前目标文件不存在，批准后文件创建且内容一致。
- 发送取消后，原回合以 user_cancelled 结算。
- 回合产生首条增量后主动断开 WebSocket，重新订阅同一会话后收到原回合结束事件，未重发任务。
- 当前复测仅走已选定的 Server API。未修改或部署 MC，未验收 MC 界面、实体读屏和台式机。

## MC 接入 Server API 后的验收

MC 使用本机已验证的 2.6.3，保留旧协议适配。新版会话默认逐次审批，执行中追加输入独立排队。断线后只读确认原任务终态。

- 使用独立登录通过 wx 界面自动化真实发送两轮消息。第二轮在同一会话取回首轮口令。实际审批对话框由测试自动选择，拒绝后没有文件，批准前也没有文件，批准后内容符合预期。任务的公开说明出现在可见执行过程。两个界面测试通过。
- 通过正常客户端适配层实测真实审批、取消及活动 WebSocket 断线恢复。隔离回环模型另通过 wx Alt+Y 用量重开测试。
- 客户端、Codex 代理、打包定向回归 273 项通过。标准非管理员隔离 BuildOnly 退出 0。实际 MC 主程序的归档包含新版协议与允许的 2.6.3 构建，worker 归档包含 Codex OneDrive 配置入口，产物中无 kimi.exe。
- 本轮未替换日常 MC。打包产物未实机启动，台式机、实体读屏及跨版本旧会话迁移未验证。

## 实际打包程序的真实聊天验收

启动标准脚本生成的隔离 `mc.exe`，为笔记、聊天和 Kimi 登录分别使用测试目录。通过 Windows 原生界面选中 Kimi Code，在输入框填写测试消息并触发发送按钮。实际子进程为当前 Windows 用户已安装的 `kimi.exe`。隔离聊天数据库记录 `model=kimi/main`、`request_status=done`、有效 Kimi 会话 ID 和精确的模型回复 `FROZEN_KIMI_REPLY_731`。未运行日常安装、改动日常聊天或复测台式机。本次冻结包端到端验收覆盖发送和收取一轮真实回复。
